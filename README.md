# Watchgoose

Приём логов, метрик и трейсов по OTLP с накоплением разборов инцидентов.

Логи — Manticore, трейсы — ClickHouse, метрики — VictoriaMetrics, разборы —
PostgreSQL. Шесть детекторов на SQL находят аномалии, фильтр решает, стоит ли
событие внимания и сколько контекста приложить, отобранное уходит вебхуком.
Внешний агент или человек пишет результат разбора обратно через MCP.

При следующем срабатывании того же паттерна к событию прикладывается ранее
записанная причина и статистика решений — «помогло N из M». Модели внутри нет,
есть таблица разборов и запросы к ней.

**ИИ снаружи.** Ключей моделей внутри нет, вызовов к ним нет. Данные не покидают
периметр, модель любая, включая локальную, стоимость вызовов на владельце агента.

**Действий не выполняет.** Эндпоинта «сделать» в API нет, инструментов действия
в MCP нет. Решение применяет человек или существующая автоматика — система
записывает факт применения и результат проверки.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/4eSyH/watchgoose/main/install.sh -o install.sh
bash install.sh
```

Ставит недостающее (`docker`, `docker compose`, `openssl`), скачивает сборку под
архитектуру машины, сверяет sha256, собирает образ локально, поднимает стек.

**Требования:** Linux, ~4 ГБ ОЗУ, порты 80 и 443 наружу, запись DNS на этот
сервер, пользователь с `sudo`. Бакет S3 создать заранее — установщик его
не создаёт, но доступ проверит.

**Спросит:** домен и режим сертификата, бюджет места, параметры S3. Пароли,
токен приёма и ключ шифрования архива сгенерирует сам в `.env` с правами `600`.

> Токен администратора показывается один раз — в базе только хэш.
> `ARCHIVE_ENCRYPTION_KEY` не хранится нигде, кроме `.env`; потеряете — архив
> не прочитать ничем.

```bash
curl -s https://ДОМЕН/healthz    # версия и коммит
curl -s https://ДОМЕН/readyz     # состояние хранилищ
```

## Телеметрия

Приложения шлют в коллектор, не в Watchgoose напрямую:

| Протокол | Адрес |
|---|---|
| OTLP / gRPC | `ДОМЕН:4317` |
| OTLP / HTTP | `ДОМЕН:4318` |

Заголовок `Authorization: Bearer <токен>`, значение — `INGEST_TOKEN` из `.env`.

**Токен один на все приложения.** Коллектор сравнивает предъявленный с
единственным настроенным и в Watchgoose про каждый не ходит: второй выпущенный
токен роли `ingest` он отвергнет с 401, хотя в базе тот будет живым.

Роль `ingest` умеет только принимать телеметрию — читать логи или выпускать
токены ей нельзя.

## Обновление

```bash
bash install.sh --update              # до последней версии
bash install.sh --update --tag=1.1.0  # до конкретной
```

Вопросов не задаёт, берёт всё из `.env`. Обновляет и файлы развёртывания —
изменённые сохраняет рядом с меткой времени.

На боевом сервере держите в `WATCHGOOSE_TAG` номер, а не `latest`.

## Резервное копирование

Том **`pg_data`** — разборы, причины, статистика решений. Логи, трейсы и метрики
восстановимы из архива, это — нет.

И `.env`: без `ARCHIVE_ENCRYPTION_KEY` архив бесполезен.
