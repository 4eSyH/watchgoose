# Watchgoose

**Централизованный приём логов, метрик и трейсов с накоплением разборов
инцидентов.**

</div>

---

## Что это

Сервис принимает телеметрию по OTLP, хранит логи в Manticore, трейсы
в ClickHouse, метрики в VictoriaMetrics, а в PostgreSQL держит производную
структуру: каталог паттернов, инциденты, причины, статистику применённых
решений.

Поверх хранения работают шесть детекторов на обычном SQL. Найденное проходит
через фильтр, который решает, стоит ли событие внимания и сколько контекста
к нему приложить. Отобранное уходит наружу вебхуком. Внешняя система —
ИИ-агент или человек — читает контекст и пишет результат разбора обратно
через MCP.

Накопленный разбор используется при следующем срабатывании того же паттерна:
к событию прикладывается ранее записанная причина и статистика решений
(«помогло N из M»). Это единственный смысл, в котором система «учится» —
никакой модели внутри нет, есть таблица разборов и запросы к ней.

### Границы

| Делает | Не делает |
|---|---|
| принимает и хранит логи, метрики, трейсы | не содержит ИИ внутри и не вызывает модели |
| находит аномалии детекторами на SQL | не выполняет операций над сервисами |
| решает, нужен ли внешний разбор и с каким контекстом | не хранит учётных данных прода |
| отдаёт данные и принимает результаты по MCP | не заменяет Grafana для графиков и трендов |
| накапливает разборы и переиспользует их | |

Эндпоинта «выполнить действие» в API нет. Инструментов действия в MCP нет.
Решение применяет человек или существующая автоматика; система записывает
только факт применения и результат проверки.

**ИИ вынесена наружу.** Внутри нет ни ключей моделей, ни вызовов к ним.
Данные не покидают периметр, модель может быть любой, включая локальную,
а стоимость вызовов лежит на владельце агента.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/4eSyH/watchgoose/main/install.sh -o install.sh
bash install.sh
```

Установщик сам поставит недостающее (`docker`, `docker compose`, `openssl`),
скачает файлы развёртывания и сборку под архитектуру машины, сверит её
контрольную сумму, соберёт образ локально и поднимет стек.

### Что нужно на сервере

- Linux, ~4 ГБ ОЗУ, диск под выбранный бюджет хранения
- Порты **80** и **443** открыты снаружи — по 80 проверяется владение доменом
- Запись DNS домена указывает на этот сервер
- Пользователь с `sudo`
- Бакет S3 создан заранее, если включаете архив (установщик его не создаёт,
  но доступ проверит)

### О чём спросит

Домен и режим сертификата, бюджет места, параметры S3. Пароли к хранилищам,
токен приёма и ключ шифрования архива генерируются сами и складываются
в `.env` с правами `600`.

> **Токен администратора показывается один раз.** В базе лежит только его
> хэш, показать повторно невозможно. Сохраните его сразу.

> **Ключ шифрования архива не хранится нигде, кроме вашего `.env`.**
> Батчи уезжают в S3 уже закрытыми, ключ выводится из парольной фразы
> и рядом с данными не лежит. Потеряете — архив не прочитать ничем.

### Проверка

```bash
curl -s https://ВАШ-ДОМЕН/healthz    # версия и коммит сборки
curl -s https://ВАШ-ДОМЕН/readyz     # состояние четырёх хранилищ
```

## Как слать телеметрию

Приложения шлют по OTLP **в коллектор**, а не в Watchgoose напрямую:

| Протокол | Адрес |
|---|---|
| OTLP / gRPC | `ВАШ-ДОМЕН:4317` |
| OTLP / HTTP | `ВАШ-ДОМЕН:4318` |

Заголовком `Authorization: Bearer <токен>`. Значение — `INGEST_TOKEN`
из `.env` на сервере.

**Токен один на все приложения.** Коллектор сравнивает предъявленный токен
с единственным настроенным значением и в Watchgoose про каждый не ходит.
Второй выпущенный токен роли `ingest` он отвергнет с 401, хотя в базе тот
будет числиться живым.

Роль `ingest` умеет ровно одно — принимать телеметрию. Утечка означает, что
вам зальют мусор; прочитать логи или выпустить новые токены ей нельзя.

## Обновление

```bash
# закрепить версию в .env
WATCHGOOSE_TAG=1.1.0

# переустановить: файлы и .env не перетираются
bash install.sh
```

На боевом сервере держите в `WATCHGOOSE_TAG` номер, а не `latest`: иначе
переустановка однажды принесёт версию, которой никто не ждал.

## Что резервировать

Том **`pg_data`** — в PostgreSQL лежат разборы инцидентов, причины
и статистика решений. Логи, трассировки и метрики восстановимы из архива,
а это — нет.

И сам **`.env`**: без `ARCHIVE_ENCRYPTION_KEY` архив бесполезен.
